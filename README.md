# Auction Desk

**チャットで調査依頼 → ログイン済みChromeで取得 → プログラムで比較 → Siteで結果と履歴を閲覧**する中古車市場調査の仕組みです。特定車種の優先設定はありません。GPT API・APIキー・別サーバーは不要です。

## 現行の対象と判断ルール
- 関東・国産乗用車・商用車除外。対象出品日は1日。
- 仕入れ予想中央値100万円以内。開始価格で予算判定しません。
- 開催一覧を車種別に集計し、出品台数が多い車種から不足相場を取得します。
- 同型式・同年式・同グレード、距離±2万km、評価±0.5の成約を比較。仕入れ側・USS側とも最低3件。R/RA等と流札は混ぜません。
- 仕入れ側とUSS側の成約中央値の差額で順位付け。同一車種は算定可能な最大差額の1台まで、最大TOP5。マイナスも含み、不足分を水増ししません。
- USS過去4開催を確認。取得7日以内・成約35日以内の根拠を再利用します。
- 価格基準不明は保留。ユーザーが認めた暫定比較のみ同一基準を仮定し、その旨を表示します。
- 諸経費・修理費・色・装備差・会社間評価差は未補正。故障・判読不能・見送り判断を明記します。

全一覧を処理しても全案件の利益判定完了とは限りません。算定済み・対象外・不足を分け、検索した車種・型式・年式帯と取得件数を記録します。特定車種の検索例を検索優先順位に使いません。

## 最初の実行
1. リポジトリ全体を取得し、Node.js 20以上を用意します。追加npm依存はありません。
2. [移行手順](docs/portability.md)に従って同梱の2スキルを登録します。
3. 利用するChromeでJU／TC-Web／CISへログインします。CISはローカルのUSBキーを接続し相場検索まで開きます。
4. チャットで対象開催日・会場を指定して調査を依頼します。車種指定なしなら出品台数順で横断調査します。
5. [バッチ処理](docs/batch-screening.md)で取得済み一覧と成約を照合し、不足相場を追加取得して再算定します。
6. 上位案件の詳細・出品票を確認し、[Site記録手順](skills/auction-desk-poc/references/chat-history.md)で新しい履歴として公開します。

## 結果と履歴
[既存Site](https://auction-desk-prototype-261111.leafycycle4.chatgpt.site)のトップは最新結果、左カラムの履歴ページは過去の調査です。調査実行日を日本時間で記録し、同日でも別実行は別ID。訂正は新しい記録として追加します。

調査データはSite専用ソースに保持し、この一般コード用GitHubには含めません。Siteへの反映はチャット作業による公開で、無人の自動検索ではありません。Google Sheetsは接続ツールを使い、依頼された場合に登録します。

## 構成
|場所|役割|
|---|---|
|skills/uss-market-search/|ブラウザ調査・軽量取得・根拠確認|
|skills/auction-desk-poc/|結果記録・Site公開・Sheets納品|
|lib/batch-screen.js|全件判定・不足検索キュー・車種重複なしTOP5|
|lib/batch-report.js|Site用の調査記録作成|
|scripts/import-cis-cache.mjs|CIS表示行の変換|
|scripts/merge-captured-comps.mjs|TC表示行と既存成約の統合|
|web/|最新結果・履歴・出力画面|
|tests/|合成データによる検証|

```sh
node --test tests/*.test.mjs
node scripts/serve.mjs
```
ローカル表示は http://localhost:4173 。調査から公開までのコマンドとハードコード箇所は[移行手順](docs/portability.md)を参照。

## 旧コードの扱い
`extension/` と `web/connector.html` は過去の試験実装で、現行の調査入口ではありません。任意車種対応の自動検索機能として起動・配布しないでください。`extension/core.js` の正規化・統計関数だけは現行バッチから参照しています。旧拡張の制約・判定は現行仕様ではなく、再利用する場合は別途実装と実機検証が必要です。

Cookie・パスワード・USBキー情報はGitやSiteへ送信しません。調査は入札・購入・出品操作を含みません。
