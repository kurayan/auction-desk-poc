# 調査開始前の準備（V1 / 1.0.0）

Chromeが閉じた状態、またはキー常駐停止状態から、JU・TC-Web・CISの検索条件画面まで準備する。Readyのみの依頼では検索・相場取得・計算・Site公開を実行しない。

## 起動と認証

1. 利用可能なアプリ・ブラウザ・タブを確認する。既存の調査用Chromeがあれば再利用する。別用途のプロフィールには触れない。
2. キー常駐停止が分かっている場合は、CISを開く前に既存「セキュリティキー」（CQKWatch.exe）を1回起動する。アプリID・パスはそのマシンで発見する。起動権限はこの利用者から承認済み。別利用者へ権限を転用しない。
3. Chrome未起動なら既存Chromeを起動し、プロフィール選択画面で調査用プロフィールを開く。この利用者の検証環境では表示名 `kurayan320`。別環境では名前を仮定せず確認する。接続後はブラウザ・タブを再発見し、古いIDを使わない。
4. CISは新しいタブで `https://ssl.cis6200.jp/` を開き、画面のログイン入口と保存済みログイン情報を使う。`www.cis6200.jp` を代用しない。TOP → 相場検索 → ダイレクト検索へ進む。
5. TC-Webは `https://taacaa.jp/` から保存済み情報でログインし、「下見検索」へ進む。 調査中にTC-Webのセッションが切れた場合も、この利用者の調査用Chromeで保存済み情報を使って通常の再ログインをそのまま実行する。ログイン成功と対象日・会場・条件を確認し、最後に取得済みの出品を照合して重複なく再開する。本人の操作が必要な認証や認証エラーが出た場合は、その画面と再開位置を知らせる。
6. JUは `https://www.junavi.jp/` からログインし、車両検索条件画面へ進む。「同意してログイン」などの同意操作は適用される確認ルールに従う。新しい規約への同意まで過去のログイン許可に含めない。

Cookie・パスワードを抽出・転記・ログ出力・Git登録しない。ログイン画面の全文取得は資格情報を含む場合があるため避け、必要な操作要素だけ確認する。

## 判定時の注意

- 常駐アプリには操作できるウィンドウがない場合がある。「targetable windowなし」やアプリ一覧の `isRunning:false` だけで起動失敗と決めない。起動操作後はCIS認証を1回試し、ログイン後の相場検索画面で判定する。失敗表示だけを理由に重複起動しない。
- 保存済み情報がDOM取得では空に見えても、画面には入力済みの場合があった。空欄と断定する前に実画面で確認し、値自体は記録しない。
- キー認識後にタブを開き直すことで復旧した実績がある。SSL警告の原因がキー未起動と断定されたわけではない。警告は迂回せず、キー状態を整えて正規URLを新しいタブで1回開き直す。なお失敗すれば停止し、状況を報告する。
- ナビゲーションのクリックで画面が変わらない場合は現在状態を確認する。表示リンクの実際のURLへ移動できるが、会員URLの推測・固定やページ内関数の直接実行はしない。

## Readyの条件

|サイト|確認する画面|
|---|---|
|JU|ログイン後の車両検索条件と検索ボタン|
|TC-Web|ログイン後の下見検索・メーカー／車種の選択入口|
|CIS|認証後の相場ダイレクト検索・フリーワード欄と検索ボタン|

3サイトすべての到達を現在の画面で確認してReadyと報告する。一部だけならサイト別に未完了理由を示す。準備したタブは操作ツールの保持機能で残す。Readyは接続準備の完了であり、検索条件適用・車両取得・市場全件判定の完了ではない。認証期限切れや中断後は再確認する。
