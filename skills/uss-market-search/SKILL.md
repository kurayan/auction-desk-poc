# USS 過去相場検索

調査開始時と履歴保存後に、リポジトリ直下で `python scripts/market-db.py sync <Siteのdist/history> <非公開キャッシュディレクトリ>` を実行する。型式・車名で `python scripts/market-db.py find S321V` のように既存履歴を確認する。一括判定では `python scripts/market-db.py export market-cache/reuse.json` を実行し、そのファイルを screen-all.mjs の --cache に渡す。鮮度・成約状態・重複判定は既存の判定処理を通す。DB、実車データ、書き出し先は非公開で管理する。

V1 / 1.0.0。起動・ログイン・Ready確認では [調査開始前の準備](references/startup-ready.md) を読む。準備だけの依頼では検索や公開に進まない。
## チャット依頼とSite履歴（現在の運用）

調査の主な指示はチャットで受け、結果は既存Auction Desk Siteへ追加する。過去の記録を消さず、日本時間の調査実行日ごとに履歴を残す。同日の別調査も別IDにする。車種指定なしでは出品台数順で横断調査し、特定車種を優先しない。

保存・公開時は `../auction-desk-poc/references/chat-history.md` を読む。ローカルのJSON追記だけでは完了ではなく、Sitesの公開成功を確認して調査別URLを返す。実際の調査データを一般コード用GitHubに入れない。記録されていない実行時刻や価格差を補わない。

ユーザーが利用するChromeのCISで、指定された車両条件に近い過去出品を検索する。JU・TCからの仕入れとUSS売却の候補調査では [オークション間売買の調査](references/cross-auction.md) を読む。検索だけの依頼では比較調査に広げない。

## 検索

案件一覧・スプレッドシート納品では [Googleドライブへの納品](references/sheets-delivery.md) も読む。継続条件は関東、国産乗用車（商用車除外）、仕入れ上限100万円。上限近辺も対象とし、任意の安全余裕で予算を下げない。順位は出品案件単位。ただし同一車種は最高差額の1台までとする。

広い候補探し・デモ・トークン節約の依頼では [軽量調査](references/lightweight.md) を先に適用する。一次選別では一覧を使い、最終候補のみ詳細・出品票を確認する。未確認車を売買推奨にしない。

1. 利用可能なブラウザ操作ツールの説明を読み、開いているChromeのCISタブを特定する。ログイン済みセッションを使う。会員固有URL・認証情報をこのスキルに固定しない。未ログインならReady手順で保存済み情報による通常ログインを試し、解決できない認証待ちだけ報告する。
2. 初回または画面変更時は [CISの確認済み画面](references/cis-workflow.md) を読む。TOP → 相場検索 → ダイレクト検索が確認済みの経路。
3. 車種・型式を基本に、依頼されたグレード、年式、走行距離、評価点、色、駆動、装備を指定する。未指定条件を勝手に固定しない。まず検索できる情報で進め、同名車種や型式が曖昧で比較に影響する場合に確認する。
4. 会場と対象期間を確認する。USSのみの依頼に提携会場を混ぜない。初期表示を無条件に信頼せず、今回使用した条件を記録する。「過去4開催」は「過去4週間」や全履歴とは異なる。
5. 検索後の条件表示と対象件数を確認する。表示件数・ページ送りは必要な調査範囲に合わせて操作する。サンプル調査なら取得件数と総件数を区別し、全件を調べたと記載しない。
6. 比較に使う車両の詳細・出品票を開き、グレード、駆動、走行距離、装備、注意事項を確認する。画面の文字情報と出品票が食い違う場合は両方を残す。読み取れない部分は未確認とする。

操作は画面から確認した要素を使い、操作後の状態を確認する。古い要素番号、推測URL、ページ内JavaScript関数の直接実行を検索の仕組みにしない。検索依頼を入札・落札・出品・有料申込の許可として扱わない。

## 記録と比較

各出品を「会場＋開催日＋開催回（分かる場合）＋出品番号」で識別する。同じ車両の再出品を同一出品と誤認しない。

記録項目は、取得日時（日本時間）、検索条件、対象件数／確認件数、会場、開催日、開催回、出品番号、車種、型式、グレード、年式、走行の原表示、出品票の走行km、色、シフト、駆動、装備、評価点、内装評価、セリ結果、応札額の原表示と単位、スタート金額、出品票の注意事項、詳細URL。

- 「落札」が明示された出品だけ、応札額を落札価格として集計する。流札・未確認等は別に扱う。
- 価格単位を画面で確認してから円／万円へ変換する。税・手数料を含む総額だと推定しない。
- 一覧の走行距離は概数の場合がある。出品票の実数が読めたら別欄に記録する。「*」等の記号を捨てず、意味が未確認なら推測しない。
- R、RA、***等の評価を通常評価と混ぜて平均しない。評価や修復歴の意味は確認できた根拠で扱う。
- 型式やグレードが異なる車両を比較対象に含めるなら違いを明記する。年式・走行・評価・装備の差を根拠なく金額補正しない。
- 他社出品との比較は、提供された情報または別途確認した情報を使う。会社間の評価基準が同じだと仮定しない。予定車両のスタート価格とUSSの落札価格は列を分ける。

回答は検索条件、比較用の表、重要な条件差、未確認事項を簡潔に示す。ファイルが有用ならCSV等に保存する。認証トークンやアカウント情報を汎用スキルや比較資料に含めない。


## 現在の仮確定運用
リポジトリの `docs/portability.md` と `docs/batch-screening.md` を参照。出品対象日は1開催日。開催一覧の車種別台数を集計し、多い車種から不足相場を取得する。同一車種1台までの差額降順TOP5（マイナス可）。算定不足で5車種に満たなければ水増ししない。調査車種・型式・年式の範囲を明記する。
